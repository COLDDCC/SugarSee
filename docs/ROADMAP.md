# 路线图与 Agent 交接

**当前任务：只保留讨论结论，不开始代码开发。**

## P0 — 产品定义（当前）
- 保留 README 和 docs 中的决策、假设、争议与待验证项。
- 核查 SugarSee 品牌、域名、商标和应用商店重名。
- 决定首发平台、目标国家/语言、糖数据口径。
- 做 3–5 个真实用户场景与移动端线框稿。
- 确认可用营养数据源、授权、成本及覆盖。

## P1 — MVP（待批准）
- 手动/快捷记录 + 编辑删除。
- 饮食照片识别（用户确认份量/糖量）或包装标签录入。
- 今日已记录糖量与方糖可视化。
- 时间线、简单周报；数据来源及估计提示。
- 基础本地数据/账号策略及隐私控制。

## P2 — 验证后扩展
- 商品/饮料数据库，条码扫描，品牌与地区区分。
- 月报、可分享卡片、个性化提醒、会员试验。
- 皮肤/精力/睡眠自我观察趋势。

## P3 — 探索性功能
- AI 趣味插画、糖人格、糖怪兽、精细化个性化报告。
- 不上线虚构未来皮肤、血糖等医学预测。

## Agent 工作协议
1. 先阅读 README 及 docs 全部内容。
2. 区分「确定方向」「待验证假设」「未批准开发」。
3. 设计以视觉化、低认知负担、少文字为先。
4. 新的医学、营养、商业数据须提供可核查来源，不能捏造。
5. 不未经许可删除或覆盖用户已经确认的产品方向。
6. 每次建议按：现状 → 问题 → 方案 → 优先级 → 验收标准 → 待用户决策。
7. 用户批准编码后，再提出技术架构、测试、分批实现与验收。
8. 重要新决策同步更新文档和变更记录。
